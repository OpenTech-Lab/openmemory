# Release v0.1.11

- Date: 2026-08-06
- Server version: 0.1.11
- Web version: 0.1.11

## Changes

- feat: Plan & Usage card on the agent detail page for the built-in Claude
  Code agent — a new `GET /agents/:id/claude-usage` endpoint resolves the
  agent's own recorded path, walks it for a `.claude` ancestor (never a
  hardcoded name match, so it survives a rename and naturally excludes
  Codex/Gemini/Copilot), reads the local `.credentials.json` OAuth token
  server-side, and calls Anthropic's `oauth/usage` endpoint to surface
  subscription plan, 5-hour and 7-day rolling-window utilization, and extra
  usage credit spend (preferring the newer `spend` field over `extra_usage`
  when both are present). The response is a flattened summary that never
  contains `access_token`/`refresh_token`; results are cached in-memory for
  90s on success (15s on transient failure), and an expired token never
  triggers a network call or a credentials rewrite. New
  `OPENMEMORY_HOME_DIR` compose env var fixes a real bug where the server
  container's `HOME` resolves to `/` (not the mounted host home) under the
  `useradd --no-create-home` + `user:` override combination — a new
  `resolve_user_path()` helper prefers `OPENMEMORY_HOME_DIR` and falls back
  to `HOME` only if unset, without touching the existing `token_file_path()`/
  `resolve_api_token()` machinery that intentionally still uses `HOME` for
  the writable token file.
- feat: `/agents/usage` cross-agent usage dashboard — a new
  `GET /agents/usage-summary` endpoint LEFT JOINs `watcher_agents` against
  `sessions` (and a 30-day `generate_series` for zero-filled sparklines) so
  every configured agent appears, including ones with zero recorded
  sessions, without fanning out the expensive per-agent subagent/skill scan
  used by `/agents/:id/stats`. The dashboard shows totals, a per-agent card
  with session/message counts, last-active time, and a lightweight inline-SVG
  sparkline (or a "No sessions recorded yet." state for zero-data agents),
  and reuses the existing `ClaudePlanUsage` card unmodified for whichever
  agent supports it. Also fixes a pre-existing sidebar bug where `/agents`
  double-highlighted alongside `/agents/sessions`, extending the same
  special-case already used for `/projects`.
