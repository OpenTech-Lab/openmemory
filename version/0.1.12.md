# Release v0.1.12

- Date: 2026-08-06
- Server version: 0.1.12
- Web version: 0.1.12

## Changes

- feat: "Design" tab on `/projects/{id}` for storing and rendering mermaid
  diagrams — a new `project_designs` table (freeform title/kind, mermaid
  source kept in the DB, not on disk, so it works even for projects with no
  filesystem path) backs a standard CRUD API
  (`GET/POST /projects/:id/designs`, `PUT/DELETE /projects/:id/designs/:design_id`).
  Kinds cover both code projects (UI, structure, workflow, DB schema,
  sequence, deployment) and narrative projects like this instance's own novel
  project (characters, plot, timeline, world, factions), each with a
  starter mermaid template that auto-fills when picking a kind on a new,
  untouched doc. Diagrams render client-side via `mermaid` (dynamically
  imported with `ssr:false` and `securityLevel: 'strict'`, keeping it out of
  the main bundle and re-rendering on theme change), with parse errors shown
  inline instead of white-screening the tab.
- feat: read-only `docs/design/` browsing — a new
  `GET /projects/:id/design-assets` endpoint scans a project's registered
  `docs/design/` folder (plus a depth-limited scan for stray `.pen` files
  elsewhere), classifying entries as Pencil (`.pen`), markdown, or other, and
  never requires a `.git` repo (a new `resolve_project_root` helper, unlike
  the existing git-only `resolve_git_project_root`, so non-git projects like
  `/home/toyofumi/projects/test` still get a valid empty result instead of a
  404). `.pen` files are only ever listed/located here — this pass does not
  open, parse, or edit them; that stays with the Pencil MCP tool. For
  projects with a path but no `docs/design/` folder yet, the panel shows a
  copy-to-clipboard `mkdir`/README command instead of writing to disk itself
  — the server container's home-directory mount is read-only by design, and
  this feature doesn't change that.
- No MCP changes in this pass — `design_save`/`design_list` tools are
  explicitly out of scope for now; this is web-only editing.
